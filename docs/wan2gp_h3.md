# H3 workflows in WanGP

H3 video generation in MediaOverload is **Powered by WanGP**. Krea image generation and refinement use ComfyUI; H3 rendering uses the official WanGP Python API in its isolated environment.

| Existing strategy | Production workflow | H3 model | Conditioning |
|---|---|---|---|
| `native_h3_t2v_story` | `wan2gp_h3_t2va` | FL2VA Pruned GGUF | Prompt only |
| `native_h3_story`, image animation | `wan2gp_h3_i2va` | FL2VA Pruned GGUF | `image_start`, `S` |
| `native_h3_fl2va_story` | `wan2gp_h3_fl2va` | FL2VA Pruned GGUF | `image_start` + `image_end`, `SE` |
| `native_h3_l2va_story` | `wan2gp_h3_l2va` | FL2VA Pruned GGUF | `image_end`, `E` |
| `native_h3_ref2va`, `text2image2native_h3_ref2va` | `wan2gp_h3_ref2va` | **Ref2VA** Pruned GGUF | Ordered `image_refs`, `I`; optional `video_guide*`, `V-U` / `V+-U` / `V+*-U` |

Long-video recipes, animated stickers and game-sprite motion also call `wan2gp.render_h3`. The planner retains their prompt generation, Krea candidate selection, human review, editing, native audio, QA and publishing policies. The backend does not choose an alternate mode when conditioning is missing.

First/end images constrain the timeline. Reference images provide subject, appearance or environment information without becoming an opening frame. The project supports up to nine reference images and three reference videos. Reference order and `<Picture N>` / `<Video N>` labels remain stable. Reference audio remains disabled in the current product contract; output audio is generated by H3.

The upstream H3 implementation also supports continuation, positioned frame injection, control-video guidance, video editing and audio references. These are separate capabilities, not additional active MediaOverload generation strategies. See the [pinned H3 handler](https://github.com/deepbeepmeep/Wan2GP/blob/6479db36bdc2619a904a852bba9c2d78e1a83f82/models/minimax_h3/minimax_h3_handler.py), [API](https://github.com/deepbeepmeep/Wan2GP/blob/6479db36bdc2619a904a852bba9c2d78e1a83f82/docs/API.md) and [settings flags](https://github.com/deepbeepmeep/Wan2GP/blob/6479db36bdc2619a904a852bba9c2d78e1a83f82/docs/SETTINGS.md).

## Local installation

`configs/wan2gp.yaml` points to the verified local installation, currently `D:/Wan2GP_benchmark`. Set `WAN2GP_ROOT` to override that path. The renderer launches `venv/Scripts/python.exe` on Windows, keeping its Torch / CUDA dependencies separate from the app and ComfyUI.

The installed revision is `6479db36bdc2619a904a852bba9c2d78e1a83f82` (WanGP 17.17). Profile 4 and Sage2 match the measured configuration. See [the installation and matched benchmark](research/wan2gp_local_benchmark_2026-10-08.md) for exact packages and asset provenance.

Register the existing local GGUF models after preparing the isolated environment:

```powershell
python scripts/setup_wan2gp_h3.py --wan-root D:/Wan2GP_benchmark --comfy-root D:/ComfyUI_windows_portable/ComfyUI
```

The setup registers FL2VA and Ref2VA definitions with Q4 diffusion and Q4 / Q2 text encoders. Q4 is the production default. WanGP's video VAE can reuse the existing video-VAE file. Its **audio VAE must use the original `weight_g` / `weight_v` format**, not the Comfy fused serialization. The original local file is 605,429,308 bytes; the earlier benchmark verified numerical equivalence to the fused VAE.

Asset checks cover the isolated interpreter, model definitions, local diffusion and text encoder files, both VAEs, tokenizer files and latent upscaler. No obsolete Comfy H3 graph or automatic backend fallback remains in the production catalog. The historical Comfy graph under `scripts/fixtures/` is only for reproducing the earlier comparison.

## Runtime and delivery

One worker initializes the official API once per app runtime. Each job records the effective settings, exact conditioning-file hashes, progress events, generation time, delivered media and ffprobe results. It unloads models through the public `session.close()` after generation, while retaining the initialized runtime so Krea and review can use the GPU. An occupied ComfyUI queue blocks a WanGP submission; an idle Comfy server unloads its models before generation.

H3 requires a 32-pixel grid and `17n+5` native frames, with at least 107 native frames in this integration. The adapter generates enough aligned frames, then preserves the caller's output canvas, frame count and 24 FPS. Frame sampling retains both timeline endpoints, and audio is retimed to the delivered duration. Already aligned outputs are copied without re-encoding. Native story settings of 362 frames remain unchanged; existing 120 / 240-frame consumers receive exactly their requested frame count.

The delivery step can resample frames and pad an unaligned canvas. Effective native dimensions and frame count are explicit in `wan2gp_settings_*.json`; delivered values appear in `wan2gp_h3_summary.json`. A speed comparison must use the same input and delivery contracts.
